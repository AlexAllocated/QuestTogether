## Changes and evidence

| Area | Corrected behavior |
| --- | --- |
| Objective history | Keeps the highest observed value per objective identity during one accepted quest lifetime. Temporary regressions, missing rows, and manual scans cannot reannounce already-observed milestones. Displayed quest values can still decrease; only repeated milestone announcements are suppressed. A new acceptance or fresh enable establishes a new baseline. |
| Quest lifecycle | Acceptance/removal callbacks carry identity tokens. Turn-in and removal retire the old quest lifetime, preventing queued reads and stale snapshot rows from resurrecting it. Late turn-in can still use retained removal metadata. |
| Snapshot reads | Distinguishes unknown counts/rows from a confirmed empty log, builds snapshots before committing them, and preserves prior state during restrictions or incomplete reads. Cached quest-log indices are checked against current row identity. |
| Completion status | Accessible false status values can clear cached complete/ready flags. Unknown or restricted reads preserve the cache. |
| Task areas | Completed quests do not generate a spurious deferred area exit. Incomplete scans preserve active area state. Loading screens reset the logout flag and old pending announcement intent. |
| Deferred work | Store and entry identity invalidate obsolete timers after reset; immediate work supersedes parked work; flushing cannot resurrect a callback consumed by another callback. Finished keys release generation bookkeeping. |
| Bubble lifecycle | Stopped bubbles are discarded rather than replayed. Hide-own and scope changes refresh active bubbles. Player announcements survive unrelated quest-icon cleanup. Live unit identity overrides recycled-frame hints. |
| Visual teardown | Keeps addon-owned visual handles until guarded cleanup can finish, including offscreen plates. Restricted cleanup resumes on events without polling. Startup timers from previous enable/test lifetimes are invalidated. |
| Identity | Uses full character/realm identity and preserves all `UnitFullName` returns. Transport sender remains authoritative; conflicting GUIDs fail closed. |
| Comms | Checks send results, resolves channel IDs after joining, preserves request-lifetime response deduplication, tolerates completion before compare entries, reports partial timeouts, and rejects/trims oversized encoded payloads at UTF-8 boundaries. |
| Settings | Open color-picker callbacks and personal-bubble edit sessions are bound to their originating profile. Stale edits cannot overwrite a switched/copied/reset profile. |
| Testing | Test state detaches from live runtime aliases and restores diagnostic counters. New regression cases use addon-owned wrappers/private fixtures and are included in `/qt test`. |

## Taint approach

The fixes keep runtime data in addon-owned tables, gate foreign objects before reading members, treat unreadable protection/visibility results as unavailable, and defer mutation during restrictions. Tooltip parsing no longer calls `TooltipUtil.SurfaceArgs` on Blizzard-returned tables. Personal bubble dirty-state bookkeeping no longer writes into Blizzard's Edit Mode manager. These removals reduce shared-state coupling; they are not claimed as independently reproduced engine taint faults.

`pcall`/`xpcall` is used for error containment and diagnostic capture, **not** as a taint barrier. Neither global error handlers nor Blizzard API tables are replaced. Callback failures retain stack context when the client exposes it and normal event errors are forwarded to the existing handler.

Relevant patterns include [scheduled identity checks](https://github.com/Tercioo/Plater-Nameplates/blob/99860a925aac6317061aa8ec4098f1be70c517df/Plater.lua#L1469), [removal-time caching and cancellation](https://github.com/Tercioo/Plater-Nameplates/blob/99860a925aac6317061aa8ec4098f1be70c517df/Plater.lua#L4253), and [avoiding secure nameplate attachment](https://github.com/Tercioo/Plater-Nameplates/blob/99860a925aac6317061aa8ec4098f1be70c517df/Plater.lua#L5158). ## Diagnostics and validation

- `/qt diagnostics [questID]`: copyable client/build/profile/options, restrictions, cached quest/area/bubble state, pending work, comms counters, errors, and recent logs. Optional quest details come from the existing cache, without probing live quest or tooltip data.
- `/qt dump`: timestamped and sequenced events. Every announcement display decision is retained; high-volume transport chatter is sampled with exact counters. Unchanged area scans are deduplicated. History is bounded to 1,000 entries/200,000 characters, individual messages are capped, and dropped history is counted.
- `lua scripts/test.lua`: deterministic offline suite. `lua scripts/test.lua . reverse`: reverse-order isolation check. `luac -p` checks Lua parsing. New regression fragments also load through the TOC for `/qt test`.

Final offline validation: **300/300 tests pass** in both normal and reverse order (baseline: 225 tests). All 17 Lua files parse; TOC entries resolve; version-script syntax and diff whitespace checks pass. Reverse ordering also exposed and fixed a test-only announcement-suppression flag leak and two missing emote fixtures, so those tests cannot trigger live emotes.
